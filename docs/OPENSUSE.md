# Порт на openSUSE Tumbleweed

Исходный проект: https://github.com/MixaDoDs/AngelOS-Dotfiles, исходный commit `932abb2a927f05ac8cc8352374ac12e4dbaf0211`.

Репозиторий порта: [Artemnuhka/AngelOS-Dotfiles-openSUSE](https://github.com/Artemnuhka/AngelOS-Dotfiles-openSUSE). При подготовке также сохранены изменения существующего коммита `fee7272` этого репозитория.

## Установка

Запускайте установщик обычным пользователем **в целевой openSUSE**, не от root.

```bash
INSTALL_BOTH_SHELLS=1 DESKTOP_SHELL=angelos ./install.sh
# Либо сразу активировать Noctalia:
INSTALL_BOTH_SHELLS=1 DESKTOP_SHELL=noctalia ./install.sh
```

`DESKTOP_SHELL` выбирает активную оболочку. `INSTALL_BOTH_SHELLS=1` добавляет пакеты и настройки обеих оболочек, чтобы переключаться командой `angelos switch noctalia|angelos`. `DOTFILES_MODE=tech` без явно выбранной оболочки сохраняет минимальный режим.

Из стандартной панели Noctalia убраны необязательные Claude Code и Speedtest виджеты. Первый несовместим с API пакетной Noctalia 5.2.1, второй требует загрузки отдельного плагина до проверки конфига. Их можно подключить отдельно после проверки совместимости. Остальные плагины исходного конфига Noctalia могут скачиваться из указанных в нём Git-репозиториев при первом запуске; это сторонний код, работающий с правами пользователя.

Для установки без больших необязательных загрузок:

```bash
INSTALL_BOTH_SHELLS=1 DESKTOP_SHELL=angelos \
  WALLPAPER_PACKS=none INSTALL_VOXTYPE=0 DOWNLOAD_VOXTYPE_MODEL=0 ./install.sh
```

Встроенные обои, шрифты и иконки остаются. Дополнительные подборки обоев и модель диктовки можно скачать отдельным повторным запуском.

## Пакеты и репозитории

Установщик использует zypper, обновляет метаданные, затем выполняет `zypper dup --no-recommends` и `zypper install --no-recommends`. `ZYPPER_DUP=0` отключает обновление системы. Ошибка пакетного менеджера останавливает установку до записи конфигов.

Большинство пакетов идут из штатных OSS/Non-OSS репозиториев Tumbleweed. Для оболочек добавляются подписанные OBS-репозитории с приоритетом 110:

- Quickshell: `home:AvengeMedia:danklinux`, рекомендован в [инструкции Quickshell](https://quickshell.org/docs/v0.2.1/guide/install-setup/).
- Noctalia **v5**, соответствующая TOML-конфигам исходного проекта: `home:neifua:Noctalia`, рекомендован в [инструкции Noctalia](https://docs.noctalia.dev/noctalia/getting-started/installation/).

Эти два репозитория поддерживаются сообществом; RPM-подписи проверяются. Автоматический импорт ключа ограничен репозиторием, который установщик только что добавил. Для остальных репозиториев неизвестный ключ требует ручного решения. `ADD_SHELL_REPOS=0` отключает автоматическое добавление.

Манифесты: `packages/zypper.txt`, `angelos-zypper.txt`, `sddm-zypper.txt`, `tools-zypper.txt`. Старые списки Arch/AUR оставлены как исходный справочный материал и не используются установщиком. Python-пакеты получают префикс установленного интерпретатора (например, `python313-evdev`). Используется SDDM Qt6; пакеты `sddm` и `sddm-qt6` одновременно устанавливать нельзя. Mission Center заменён на GNOME System Monitor, курсор fallback — Adwaita.

В VirtualBox установщик проверяет виртуализацию `oracle`: устанавливает гостевые инструменты и, если минимальное ядро не содержит `vmwgfx`, заменяет `kernel-default-base` на `kernel-default` одной транзакцией. После этого нужна перезагрузка. `INSTALL_VM_DRIVERS=0` отключает этот шаг; на физическом компьютере он не выполняется. `libwayland-server0` указан явно: без него Niri в минимальном образе проходит проверку конфига, но падает при запуске.

## Установка на основной компьютер

Порт рассчитан только на Tumbleweed. Успешный запуск в VirtualBox подтверждает работу установки и оболочек, но не проверяет ваш GPU, несколько мониторов, сон, Bluetooth и драйвер NVIDIA. Опциональная сборка исправленного Qt EGL плагина для NVIDIA также не проверена. Поэтому сначала используйте отдельного тестового пользователя, снимок Snapper и копию домашней папки. Snapper не заменяет резервную копию `/home`.

Установщик может обновить всю систему (`ZYPPER_DUP=1`), добавить два репозитория сообщества, записать домашние конфиги и сменить экран входа (`INSTALL_SDDM=1`). Для первого знакомства на уже обновлённой Tumbleweed сохраните текущий менеджер входа и не запускайте полное обновление внутри установщика:

```bash
INSTALL_BOTH_SHELLS=1 DESKTOP_SHELL=angelos \
  ZYPPER_DUP=0 INSTALL_SDDM=0 GRANT_INPUT_ACCESS=0 \
  WALLPAPER_PACKS=none INSTALL_VOXTYPE=0 DOWNLOAD_VOXTYPE_MODEL=0 ./install.sh
```

Затем выберите Niri на существующем экране входа. При необходимости отдельно обновите Tumbleweed обычным `zypper dup` до установки; не используйте этот пример как способ делать частичные обновления устаревшей системы.

`GRANT_INPUT_ACCESS=0` установлен по умолчанию: установщик не добавляет пользователя в `input`. Обычные сочетания Niri работают; дополнительный жест одиночного нажатия Meta может быть недоступен. `GRANT_INPUT_ACCESS=1` даёт всем процессам пользователя возможность читать клавиатуру и другие устройства ввода, а не только AngelOS. Повторный запуск с `0` не отменяет членство в группе, выданное ранее.

Существующие пользовательские конфиги сохраняются, изменённые версии кладутся в `~/.local/state/angelos/kept-updates`. Из-за этого прежний собственный конфиг Niri может не запускать новую оболочку: проверьте автозапуск или выполните `angelos switch angelos|noctalia`. Замены файлов, в том числе CLI и drop-in SDDM, сохраняют `.bak.<время>`.

## Проверки

Прогон в VirtualBox завершён успешно; подробности и границы проверки — [в отчёте](TESTING-OPENSUSE.md).

После добавления обоих репозиториев:

```bash
./scripts/check-packages.sh    # проверка полного набора зависимостей решателем zypper, dry-run
./scripts/check.sh             # синтаксис, конфиги, установка/повторная установка, обновления
bash .config/quickshell/angelos/scripts/test-ui.sh .config/quickshell/angelos
niri validate
```

## Восстановление

До установки создайте важный снимок корневой системы:

```bash
sudo snapper -c root create --type single --description 'Before AngelOS port' \
  --userdata 'important=yes' --print-number
```

Snapper `root` обычно не включает `/home`: сохраните домашние конфиги отдельно. В тестовой ВМ исходная система сохранена в снимке **11**, домашняя папка — `/home/artem/angelos-before-port-home-20261004.tar.gz`.

Для восстановления корневой системы можно выбрать снимок в меню загрузки и выполнить `sudo snapper rollback`, затем перезагрузиться. Домашние конфиги восстанавливаются отдельно из архива; архив не удаляет новые файлы, поэтому перед полным восстановлением сохраните текущие конфиги и уберите добавленные установщиком файлы. Сам установщик также сохраняет заменённые файлы с суффиксом `.bak.<время>`.

Это самостоятельный порт. Обновления через Settings → Updates используют репозиторий, из которого выполнена установка. Если новая ветка не содержит манифест openSUSE, обновление останавливается до изменения файлов. Не заменяйте установщик новым `install.sh` из исходной Arch-ветки: изменения исходного проекта нужно переносить в этот порт и заново проверять. Снимки обновления также учитывают настройки gsettings в keyfile и dconf.
